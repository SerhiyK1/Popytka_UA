# Popytka UA - Документація проекту для Gemini

## 🚗 Огляд проекту
**Popytka UA** — це додаток для спільного використання поїздок (ridesharing) на базі Flutter, розроблений спеціально для українського ринку. Він з'єднує водіїв з вільними місцями та пасажирів, які подорожують в одному напрямку, подібно до BlaBlaCar.

## 🛠 Технологічний стек
- **Framework:** Flutter (Android, iOS, Web, Windows)
- **State Management:** Riverpod (функціональний підхід)
- **Navigation:** GoRouter
- **Backend:** Firebase
  - **Auth:** Phone & Google Sign-In
  - **Database:** Cloud Firestore
  - **Storage:** Firebase Storage (для фото профілю та авто)
- **Localization:** Flutter Gen (L10n) - підтримує українську (основна), російську та англійську.
- **Architecture:** Feature-First Clean Architecture.

## 📂 Структура проекту
- `lib/domain/models/`: Основні структури даних (User, Ride, Booking, Chat).
- `lib/data/repositories/`: Firebase реалізація логіки даних.
- `lib/data/providers/`: Riverpod провайдери для стану та впровадження залежностей (dependency injection).
- `lib/presentation/`:
  - `screens/`: Організовані за функціями (auth, home, profile, publish, messages тощо).
  - `widgets/`: Багаторазові UI компоненти.
  - `router/`: Конфігурація навігації (`app_router.dart`).
  - `theme/`: Стилізація та кольори додатка.
- `docs/`: Комплексна документація щодо архітектури, схеми бази даних та розгортання.
- `scripts/`: Важливі Windows batch скрипти для керування Gradle та процесами збірки.

## ⚡ Ключові функції та поточний статус
- **Auth Flow:** Завершено (Phone/Google).
- **Пошук та бронювання поїздок:** Функціонально.
- **Опублікувати поїздку:** Повний цикл з вибором дати/часу та місця розташування.
- **Messaging (Фаза 7):** Реалізовано чат у реальному часі між пасажирами та водіями.
- **Керування профілем:** Ролі водія/пасажира, деталі авто та завантаження фото.
- **Мої поїздки:** Керування активними, запланованими та завершеними поїздками.
- **Стабільність:** Проект включає інфраструктуру "Anti-crash" та **Demo Mode** (резервний варіант, якщо Firebase недоступний).

## ⚠️ Критичні зауваження щодо розробки
- **Gradle Management:** На Windows Gradle часто переміщується на диск `D:` за допомогою скриптів у `/scripts` для економії місця на `C:`. Використовуйте `scripts/check_build.bat` для перевірки середовища.
- **Data Serialization:** Переконайтеся, що `LocationModel` та інші вкладені моделі правильно серіалізуються для Firestore (вкладені мапи).
- **Localization:** Завжди додавайте нові рядки до `lib/l10n/app_uk.arb` (та інших) і запускайте `flutter gen-l10n`.
- **Firebase Emulators:** Підтримуються та є пріоритетними для локальної розробки.

## 🤖 Інструкції для Gemini
1.  **Дотримуйтесь архітектури:** Тримайте логіку в репозиторіях (repositories), а стан — у провайдерах (providers). UI має бути в `presentation/`.
2.  **Поважайте документацію:** Звертайтеся до `docs/ARCHITECTURE.md` та `docs/DB_SCHEMA.md` перед внесенням структурних змін.
3.  **Перевіряйте статус:** Звертайтеся до `docs/CURRENT_STATUS.md`, щоб побачити останній перевірений стабільний стан.
4.  **Політика мови:** Основна мова розробки для UI рядків — українська.
